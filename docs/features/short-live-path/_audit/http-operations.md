# T9–T11 — creation, neutral status and explicit disclosure

Implemented three documented operations through thin Adonis controllers and service coordination. Runtime remains closed unless actual ownership/readiness, the restricted retained key, namespace, explicitly configured HTTPS public origin and pinned immediate proxy address are present. Untrusted Host/forwarding data never selects the Share origin. Trusted-address canonicalization and the existing generation guard wrap all request Redis operations. No accounts, replay/recovery endpoint, automatic retry, exact quota reservation or SQL-metadata rollback was added.

Creation prepares optional native Argon2 before a parameterized Lucid transaction. Its materialized PostgreSQL clock sample supplies immutable creation/expiration once; the transaction resolves only after acknowledged commit. Original hard expiry is used for Redis publication, accounting, confirmation reread and final checks. Unknown outcomes never confirm or retry; possible orphans retain their original expiry. Neutral status returns only the four allowlisted projections, validates canonical tokens before digest lookup, and uses durable expired metadata without payload reads. Explicit disclosure validates all fields, applies observed pair limits, shares the existing two-call/no-queue native work gate, confirms wrong-code accounting, preserves previous failure timestamps, rereads payload consistency and checks fresh authoritative time/current run after async work.

The actual installed Adonis response implementation was inspected: `response.send` buffers content; `response.finish()` synchronously writes a nonstreaming body. Controllers explicitly finish inside the guarded release callback, not after asynchronous tail middleware. JSON serialization happens before the final synchronous current-owner/client/clock check; no await follows that check before finish. Both POSTs implement a fatal UTF-8, scalar-validating, uncompressed JSON wire boundary of 524288 bytes, including chunked input, with safe no-store/no-referrer failures. General request/exception logging remains disabled.
